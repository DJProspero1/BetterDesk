# BetterDesk

## Register

product

## Users

Ordinary people, including accountants, receiving help while present at their Windows computer or Android phone. They should not need to understand remote access or configure anything. Helpers operate the more detailed controls.

## Product Purpose

Open-source attended remote help in both directions between Windows and Android. The primary action is opening a helper's invitation and allowing help. This strategy was established and refined with the user across the preceding design conversation, then approved for implementation.

## Brand Personality

Simple, calm, familiar. Short literal labels, generous readable controls, no technical vocabulary in the receiving flow. Name confirmed by the user: BetterDesk.

## Anti-references

No busy remote administration dashboard, account gate, setup wizard with five permissions at once, advertising, decorative metrics, or different mobile and desktop navigation.

## Design Principles

1. One obvious next action. Receiving help is the default.
2. Same components, words, states, and ordering on Windows and Android.
3. Automate configuration, never fabricate consent or connection success.
4. Clearly show who is helping, viewing versus controlling, and Stop help.
5. A stopped invitation cannot grant future access.

## Accessibility & Inclusion

Keyboard focus, screen-reader labels, large touch targets, scalable text, no status communicated by color alone, and no decorative motion. Match the system theme. English and European Portuguese copy share the same flow.

## Local development

The user authorizes private GitHub source hosting. All builds and tests run locally. No cloud builds or GitHub Actions. Initial connections use the same local network; no public service is provisioned.
